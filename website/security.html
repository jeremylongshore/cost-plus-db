Security First

Security isn't an afterthought at CostPlusDB. It's built into everything we do, from server hardening to transparent operations.

Our Security Practices

Server Hardening

  • SSH key authentication only (Ed25519 encryption)
  • Root login disabled
  • Custom SSH port (non-default)
  • Firewall (UFW) with minimal open ports
  • fail2ban intrusion prevention
  • Automatic security updates
  • NTP time synchronization
  • Log rotation and monitoring

PostgreSQL Security

  • SSL/TLS enforced on all connections
  • scram-sha-256 password encryption
  • Customer database isolation
  • Connection pooling (pgBouncer)
  • Connection logging enabled
  • Separate users per customer
  • Principle of least privilege

Backup Security

  • Encrypted backups with pgBackRest
  • Multi-region redundancy (Wasabi S3)
  • 30-day retention
  • Point-in-time recovery (7 days)
  • Regular restoration testing to verify backups work

Monitoring & Response

  • 24/7 uptime monitoring (Betterstack)
  • Automated alerts for issues
  • Daily backup verification
  • Weekly security patches
  • Incident response procedures documented

Incident Response

If something goes wrong, here's what happens:

P0: Database Down (Critical)

  1. Automatic alert to operator (SMS + email)
  2. Email to customer promptly upon detection
  3. Investigation and fix in progress
  4. Regular updates until resolved
  5. Post-mortem report within 24 hours
  6. SLA credit if downtime > 1 hour (pro-rated refund)

Security Incident

  1. Isolate affected systems immediately
  2. Email all affected customers within 1 hour
  3. Forensic analysis
  4. Remediation and hardening
  5. Detailed incident report to customers
  6. Public disclosure (if data breach)

Reporting Security Issues

Found a security vulnerability? Please report it responsibly:

How to Report

  1. Email: jeremy@intentsolutions.io
  2. Subject: "SECURITY: [brief description]"
  3. Include:
    • Description of the vulnerability
    • Steps to reproduce
    • Potential impact
    • Suggested fix (if you have one)

What to Expect

  • Acknowledgment: Within 24 hours
  • Assessment: Within 72 hours
  • Fix: Critical issues within 7 days, others within 30 days
  • Credit: We'll credit you (if you want) in our security changelog

Please do NOT:

  • Post publicly before we've had a chance to fix
  • Attempt to access customer data
  • Use automated vulnerability scanners without permission
