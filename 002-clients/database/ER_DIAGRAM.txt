================================================================================
WORKFLOW STAGE PROGRESSION
================================================================================

CUSTOMER_WORKFLOW Table - 12 Stage Onboarding Pipeline:

1.  form_submitted              ── Customer fills out intake form
    form_submitted_at

2.  consultation_scheduled      ── Discovery call scheduled
    consultation_scheduled_at
    consultation_date

3.  consultation_completed      ── Discovery call completed
    consultation_completed_at
    consultation_notes

4.  pricing_approved           ── Customer accepts quote
    pricing_approved_at

5.  payment_received           ── First payment processed
    payment_received_at

6.  database_provisioning_started ── Begin DB setup
    database_provisioning_started_at

7.  database_provisioned       ── Database is live
    database_provisioned_at

8.  credentials_sent           ── Connection details sent
    credentials_sent_at

9.  customer_confirmed_access  ── Customer verified connection
    customer_confirmed_access_at

10. migration_started          ── Data migration begins
    migration_started_at

11. migration_completed        ── Migration finished
    migration_completed_at

12. go_live                    ── Production traffic switched
    go_live_at

    current_stage              ── Text summary of current position
    blocked                    ── Is onboarding stuck?
    blocker_reason             ── Why stuck?
    workflow_notes             ── General notes

    "our_cost": 30.00,
    "your_price": 149.00,
    "quantity": 1

  {
    "description": "High Availability Add-on",

  {
    "description": "Extra Storage (+200GB)",
    "our_cost": 4.00,

This supports CostPlusDB's transparency model: show customers exactly
what we pay vs. what they pay (cost + 25% markup).

================================================================================
DATA FLOW EXAMPLE: NEW CUSTOMER ONBOARDING
================================================================================

Step 1: Prospect fills out form
    ↓
    INSERT INTO customers (status = 'prospect', ...)
    INSERT INTO customer_workflow (form_submitted = 1, ...)
    INSERT INTO activity_log (action = 'customer_created', ...)

Step 2: Discovery call
    ↓
    UPDATE customer_workflow SET consultation_completed = 1, ...
    INSERT INTO notes (note_type = 'meeting', ...)

Step 3: Customer approves pricing
    ↓
    UPDATE customer_workflow SET pricing_approved = 1, ...
    UPDATE customers SET status = 'approved', ...

Step 4: Payment received
    ↓
    UPDATE customer_workflow SET payment_received = 1, ...
    INSERT INTO billing (payment_method = 'stripe', ...)

Step 5: Provision database
    ↓
    UPDATE customer_workflow SET database_provisioned = 1, ...
    INSERT INTO databases (provision_status = 'active', ...)
    UPDATE customers SET status = 'provisioning', ...

Step 6: Send credentials
    ↓
    UPDATE customer_workflow SET credentials_sent = 1, ...
    (Email sent to customer with database connection details)

Step 7: Customer confirms access
    ↓
    UPDATE customer_workflow SET customer_confirmed_access = 1, ...

Step 8: Migration (if needed)
    ↓
    UPDATE customer_workflow SET migration_started = 1, ...
    UPDATE customer_workflow SET migration_completed = 1, ...

Step 9: Go live!
    ↓
    UPDATE customer_workflow SET go_live = 1, current_stage = 'active'
    UPDATE customers SET status = 'active', activated_at = NOW()

Step 10: Generate first invoice
    ↓
    INSERT INTO invoices (invoice_number = 'INV-...', line_items = [...])

================================================================================
TRIGGER BEHAVIOR
================================================================================

All UPDATE operations automatically trigger:
    updated_at = CURRENT_TIMESTAMP

Example:
    UPDATE customers SET tier = 'Pro' WHERE id = 123;
    ↓
    Trigger fires: updated_at = '2025-10-20 15:30:00'
    Activity log entry: old_values = {"tier": "Dedicated"},
                       new_values = {"tier": "Pro"}

================================================================================
INDEX USAGE PATTERNS
================================================================================

Frequently Queried Paths:

1. Find customer by email:
   customers.contact_email [INDEXED] → O(log n)

2. Get all active customers:
   customers.status [INDEXED] + customers.is_active [INDEXED] → O(log n)

3. Get customer's databases:
   databases.customer_id [INDEXED] → O(log n)

4. Find overdue invoices:
   invoices.payment_status [INDEXED] + invoices.due_date [INDEXED] → O(log n)

5. Support ticket queue:
   support_tickets.status [INDEXED] + priority [INDEXED] → O(log n)

6. Audit trail lookup:
   activity_log.customer_id [INDEXED] + created_at [INDEXED] → O(log n)

Without indexes, all queries would be O(n) table scans.
